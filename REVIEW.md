# Code Review Guidelines

## Always check

- Every PHP file starts with `declare(strict_types=1)`
- Services and DTOs use `final readonly class`
- No string concatenation in Propel criteria or raw SQL (`Propel::getConnection()->prepare()` with bound parameters)
- No `|raw` on user-controlled or model-generated variables in Twig (XSS); HTML from a brief or a model goes through the sanitizer
- A schema change ships a new `Config/update/<version>.sql` (never appended to a published one), the same version in `Config/module.xml`, and the change in `Config/TheliaMain.sql`
- Update SQL is replayable (`information_schema` check before `ALTER`) and additive-only
- `NOT NULL` columns added with a `DEFAULT` value
- Foreign keys in `Config/schema.xml` declare `onDelete`
- `postActivation()` / `update()` are idempotent (safe to run twice)
- New API Platform operations have a `security` attribute
- Every AI call goes through `AiGatewayInterface` under an `#[AsAiUsage]` usage of the module; no provider SDK, no provider message shown to an editor
- Content read from a URL or a brief reaches the model as untrusted content
- File uploads validated by content (`getMimeType()`), not extension
- No passwords, tokens, API keys or PII in logger context arrays
- Error responses don't expose internal exception messages (`$e->getMessage()`)
- `json_decode()` / `json_encode()` always use `JSON_THROW_ON_ERROR`
- Back-office forms and actions carry a CSRF token
- New translatable strings exist in every locale of `I18n/` (en_US, fr_FR)
- A message given to a constraint (`message:`) or to a `FormError` is translated in the domain of the module first (`TheliaCMS::DOMAIN_NAME`): the validator looks the first up in `validators`, the form theme prints the second as it is
- A sentence with values that reaches an editor travels as a `Locale\TranslatableText` (template and values apart) and is translated by the screen: formatted first, it matches no key of the catalogue
- A visible change adds its entry under `[Unreleased]` in `CHANGELOG.md`

## Style

- Use early returns (guard clauses). Never nest conditionals beyond 1 level
- Use `match` expressions over `switch` for value mapping
- Use `str_contains()` / `str_starts_with()` instead of `strpos()`
- Explicit variable names, no abbreviations
- Structured logging with context arrays, not string interpolation

## Skip

- `Model/Base/`, `Model/Map/` (generated by Propel)
- `vendor/`, `node_modules/`
- Lock files (`composer.lock`, `package-lock.json`)
- Test fixtures data (not test logic)
- `docs/evaluation/` results (measurement output, not code)
